# pair-wise-yy-59 法律文件披露、去密与发布质控工作台

用于诉讼披露批次中的区域去密、原页/发布页双人复核、文档标签和发布门禁。PDF.js 真实渲染示例文档，去密区域可绘制、确认并持久化到本地草稿。

## 版本化可恢复合并流程

质控台只留本机草稿，外聘复核员断网期间改好的清单回中心时，按版本做三方合并，避免把已变化的密级、区域和复核结论盖回去。

- **导入批带版本**：每批带文档版本 `docVersion`、区域版本 `regionVersion`、密级版本 `classVersion`、操作者和复核号 `reviewNo`（见 `src/merge/types.ts`）。
- **同批复传幂等**：同一批号再次受理直接沿用第一次结果，不重复写入、不重复盖写；同复核号也不重复落结论。
- **中心变化先失效重算**：中心区域或密级变化后，关联的**未完成**复核置为 `invalid` 并按新内容生成 `pending` 后继；**已签**复核冻结签核时的文档/区域/密级依据，只标记依据过期，结论保留可查。
- **双改冲突保留双方**：同一区域（按离线基线版本 + 内容指纹）或密级两边都改过，中心版与外聘版连同来源都保留，生成 `open` 冲突；可逐项裁决 **采用中心 / 采用外聘 / 双方保留**（外聘内容复制为新区域共存）。裁决完成前文档不能进入发布批次。
- **写入账本可从失败项重试**：区域/密级/复核的每次中心写入入账，失败的单项可单独或一键重试；已成功项不重复落地。
- **发布门禁**：未决冲突、失败写入、未签的重算复核、草稿区域任一存在都阻止生成发布批次；发布时冻结各文档版本。
- **旧草稿迁移**：没有版本号的旧文档/区域在加载时补成首版，原有区域与复核记录原样保留、继续可查，并写一条 `legacy-bootstrap` 历史。

全部状态变化写入文档内 append-only 的 `history`（区域/密级快照、复核依据、冲突开启与裁决）。

### 合并演练（页面内 3 步）

1. 文档集点「模拟中心离线期变化」：中心改 R-02 区域、把 DOC-00427 密级改为严格机密，观察未完成复核失效重算链。
2. 点「受理外聘导入批」：外聘沈确的批与中心发生区域双改、密级双改冲突；其 R-10 新区域首次中心写入失败。
3. 进入「合并与冲突」：逐项裁决冲突、从失败项重试写入；在「复核结论」页签核重算后继；通过门禁后在「发布批次」生成冻结版本的发布包。再次点受理按钮可验证同批复传沿用首次结果。

### 规则校验脚本

```bash
npx tsx scripts/verify-merge.ts
```

端到端覆盖：旧草稿迁移 → 中心变化失效重算/已签依据保留 → 外聘导入双改冲突 → 失败项重试 → 复传幂等 → 逐项裁决 → 门禁与发布版本冻结（39 项断言）。

## 技术栈

React、Radix UI 风格组件、Zustand（持久化带 v1→v2 迁移）、TanStack Router、TanStack Query、PDF.js、Vite、TypeScript。核心合并逻辑在 `src/merge/engine.ts`，不依赖 React，可独立测试。
